# 大模型私有化接入方案

## 目标与约束
- 部署方式：私有化本地部署，走 **OpenAI 兼容 HTTP 接口**（`/v1/chat/completions`、`/v1/embeddings`），适配 Ollama / vLLM / Xinference，仅用 `httpx` 不引入厂商 SDK。
- 混合模式：LLM 为主，**超时/异常/未启用时自动降级到现有规则算法**，复用已有 `is_degraded`/`is_timeout` 标识。
- 合规：案情数据仅发送至内网模型端点；`LLM_ENABLED=False`（默认）时零行为变化，现有 27 项 e2e 全部保持通过。
- 分能力开关，可单独降级任一能力。

## 一、新增 LLM 基础设施层 `app/services/llm/`
- `client.py`：`LLMClient`（模块级懒加载单例，复用 `httpx.Client` 连接池）
  - `chat_json(messages, temperature) -> dict`：请求 `chat/completions`，带 `response_format={"type":"json_object"}`，返回解析后的 JSON；超时/连接错误/非 2xx/JSON 解析失败统一抛 `LLMUnavailableError`。
  - `embed(texts: list[str]) -> list[list[float]]`：请求 `embeddings`，返回向量。
  - `ping() -> bool`：探活（`GET {base}/models` 或轻量 chat），供状态接口使用。
  - `LLMUnavailableError(Exception)`：降级信号异常。
  - 超时、重试次数、温度均取自 `settings`。
- `schemas.py`：结构化输出的 Pydantic 校验模型
  - `LLMCaseJudgement`（case_type/confidence/basis[]/fact_features[]/suspect_profile/fund_interception/followup_investigation/followup_questions[]）
  - `LLMExtractionResult`（items[]: element_code/value/evidence_snippet/confidence）
  - `LLMParseResult`（qa[]: question/answer/chapter + followup_draft[]）
  - 校验失败视为不可用（触发降级），章节/要素编号需回落到合法枚举，非法项丢弃。
- `prompts.py`：四类能力的中文提示词构造器（内置角色设定、19 类案由清单、五流要素编号表、章节枚举、强制 JSON schema 说明、"不确定则留空不得杜撰"约束）。
- `service.py`：`LLMService` 门面（持有 db，供各业务服务注入）
  - `judge_case(context, categories, key_gaps) -> LLMCaseJudgement`
  - `extract_elements(qa_text, candidate_codes) -> LLMExtractionResult`
  - `parse_record(text) -> LLMParseResult`
  - `embed_texts(texts) -> list[vector]`
  - `status() -> dict`（可达性、模型名、各能力开关）
  - `reindex_templates()`：批量计算并持久化启用模板的语义指纹向量。
- `__init__.py`：导出 `LLMClient/LLMService/LLMUnavailableError` 等。

## 二、配置与依赖
- `app/core/config.py` 的 `Settings` 新增 LLM 配置块（含中文注释，对应扩展点 12.3 Q-7）：
  - `LLM_ENABLED: bool = False`（总开关）
  - `LLM_BASE_URL: str = "http://127.0.0.1:11434/v1"`、`LLM_API_KEY: str = "not-needed"`
  - `LLM_CHAT_MODEL: str = "qwen2.5:14b-instruct"`、`LLM_EMBEDDING_MODEL: str = "bge-m3"`
  - `LLM_TIMEOUT_SECONDS: float = 30.0`、`LLM_MAX_RETRIES: int = 1`、`LLM_TEMPERATURE: float = 0.1`
  - 分能力开关：`LLM_ENABLE_SEMANTIC_MATCH/ANALYSIS/EXTRACTION/IMPORT_PARSE: bool = True`
- `requirements.txt` 新增 `httpx==0.28.1`（显式声明，当前为 starlette 传递依赖）。
- 新建 `backend/.env.example`：列出全部 LLM 环境变量与 Ollama/vLLM 部署示例注释。

## 三、能力一：语义匹配推荐（F_sem 向量化）
- `app/models/template.py`：`Template` 新增两列（均可空，演示库 create_all 自动生效）
  - `embedding: Mapped[str|None]`（Text，JSON 序列化的向量）
  - `embedding_model: Mapped[str|None]`（String，记录生成模型，模型变更即视为过期需重算）
- `app/services/ai_service.py`：
  - `recommend_templates` 入口：若语义开关开启，先用 `LLMService.embed_texts([brief])` 得到案情向量（单次调用）。
  - `_compute_semantic_factor`：改造为优先"案情向量 · 模板向量"余弦相似度；模板向量从 `Template.embedding` 读取，缺失或 `embedding_model` 不匹配时即时计算并回写持久化。
  - 任一环节抛 `LLMUnavailableError` 或开关关闭 → 回落到现有字符 bigram 余弦（`_char_bigrams`），`F_sig`/`F_cat` 不变，保证公式 `S(D,T)=α·F_sig+β·F_cat+γ·F_sem` 一致。

## 四、能力二：侦查研判建议生成
- `app/services/ai_service.py` 的 `analyze()`：
  - 保留上下文拼接与"上下文不足"短路逻辑。
  - 新增：若 `LLM_ENABLE_ANALYSIS` 开启，调用 `LLMService.judge_case(context, 全部案由, key_gaps)`，将结构化结果映射为 `CaseTypeJudgement`（含 basis 支撑链）、`InvestigationGuide`、`FactFeature[]`，并把 LLM 的 `followup_questions` 与五流重点缺口追问合并为 `SuggestionOut[]`（缺口追问仍 `is_pinned=True` 置顶，符合 GR-2）。
  - 捕获 `LLMUnavailableError` → 置 `is_timeout=True` 并执行现有规则链路（`_judge_case_type`/`_build_investigation_guide`/`_build_key_gap_suggestions`）作为兜底。
  - 规则链路整体抽取为 `_analyze_by_rules(...)`，供降级复用，逻辑与当前保持一致。

## 五、能力三：五流要素抽取（正则 + LLM 融合）
- `app/services/fiveflow_service.py`：
  - `extract_from_qa`/`_extract_single_qa`：先执行现有正则抽取（高精度），若 `LLM_ENABLE_EXTRACTION` 开启，再对同段文本调用 `LLMService.extract_elements(text, 候选要素编号)`（高召回）。
  - 融合策略：正则命中值优先保留；LLM 独有值以较低 `confidence`（如 0.6）写入并置 `need_manual_confirm=True`（对应 ER-4 低置信不自动填充、待人工确认）；要素编号需在 `FlowElementDefinition` 目录内，非法丢弃。
  - LLM 不可用时仅用正则结果，行为与当前一致；`compute_coverage`/`sync_element_status` 不改。

## 六、能力四：历史笔录解析导入
- `app/services/import_service.py`：
  - `parse_text`：若 `LLM_ENABLE_IMPORT_PARSE` 开启，优先调用 `LLMService.parse_record(text)` 得到问答对 + 章节归类 + 缺口追问草稿；章节需回落到合法 `Chapter` 枚举。
  - 解析异常/开关关闭 → 回落现有 `_extract_qa_pairs` + `_classify_chapter` + `_fallback_plain_text` 链路。
  - `analyze_parsed_qa`/`rebuild_session` 保持不变（复用五流融合抽取自动获得 LLM 增强）。

## 七、接口与启动
- `app/api/v1/ai.py` 新增两个运维接口（`require_permission` 沿用现有权限）：
  - `GET /ai/llm/status`：返回可达性、聊天/向量模型名、四项能力开关，便于内网排障。
  - `POST /ai/llm/reindex-templates`：触发 `LLMService.reindex_templates()`，管理员在模板变更后重算向量（模板管理权限）。
- `app/main.py` 的 `lifespan`：种子初始化后，若 `LLM_ENABLED` 且语义开关开启，best-effort 预计算模板向量（异常仅告警不阻断启动）。

## 八、验证
- `backend/e2e_test.py`：
  - 默认（`LLM_ENABLED=False`）跑通现有 27 项，断言行为零变化（回归基线）。
  - 新增 `GET /ai/llm/status` 断言（返回开关状态，模型不可达时 `reachable=False` 但接口 200）。
  - 新增可选环境变量驱动的用例：当 `LLM_ENABLED=True` 且端点可达时，校验研判/抽取/推荐走 LLM 路径且降级标识正确（不可达时自动降级不报错）。
- 手工冒烟：以 Ollama 拉起 `qwen2.5` + `bge-m3`，`reindex-templates` 后验证推荐匹配度、研判报告、五流抽取、历史导入四条链路的 LLM 增强效果与降级兜底。

## 假设
- 内网已具备或将部署 OpenAI 兼容推理服务；默认示例为 Ollama（`http://127.0.0.1:11434/v1`）。
- 演示库通过 `create_all` 重建，新增可空列不需要迁移脚本；已有库需删除重建或后续补 Alembic（本期不含）。
- 提示词内置的案由/要素/章节清单以现有种子数据与枚举为准。
